## 层 3：执行层 [`engine/model_runner.py`](../nanovllm/engine/model_runner.py)

ModelRunner 是"后厨总管"——把数据搬上 GPU、跑模型、采样、管理 KV cache 和 CUDA Graph、协调多卡。它很长，我们按功能分块读。

### 3.1 `__init__`：五步装配

```python
def __init__(self, config, rank, event):

    dist.init_process_group("nccl", "tcp://localhost:2333", world_size=self.world_size, rank=rank)
    torch.cuda.set_device(rank)
```

五个关键步骤，对应后面五小节。注意 `torch.set_default_device("cuda")` / `set_default_dtype` 这对"全局默认值"——让模型构造时所有张量默认在 GPU 上、默认 bf16，省得处处写 `.cuda()`，第 3 部分提过这种全局状态的做法。

> 🔬 `dist.init_process_group("nccl", ...)`：初始化 **NCCL** 进程组（[第 2c 部分 §2](02c-加速并行与采样.md) 的 all_reduce 就走它）。`tcp://localhost:2333` 是各 rank 会合的地址。rank 0 是主控。

### 3.2 多进程通信：`call` / `write_shm` / `read_shm` / `loop`

理论见 [第 3 部分 E1](03-Python语法清单.md)。看字节级实现：

```python
def call(self, method_name, *args):
    if self.world_size > 1 and self.rank == 0:
        self.write_shm(method_name, *args)      # rank0: 写共享内存 + 唤醒其他 rank
    method = getattr(self, method_name, None)    # 所有 rank: 反射取方法（第3部分 D3）
    return method(*args)

def write_shm(self, method_name, *args):
    data = pickle.dumps([method_name, *args])           # 序列化成字节
    n = len(data)
    self.shm.buf[0:4] = n.to_bytes(4, "little")         # 前 4 字节: 数据长度
    self.shm.buf[4:n+4] = data                          # 后面: pickle 数据
    for event in self.event: event.set()                # 唤醒所有 worker

def read_shm(self):
    self.event.wait()                                    # 阻塞等 rank0 唤醒
    n = int.from_bytes(self.shm.buf[0:4], "little")      # 读长度
    method_name, *args = pickle.loads(self.shm.buf[4:n+4])  # 解包（第3部分 D2）
    self.event.clear()
    return method_name, args

def loop(self):      # worker rank 的主循环
    while True:
        method_name, args = self.read_shm()
        self.call(method_name, *args)
        if method_name == "exit": break
```

**共享内存的协议**（很简单但有效）：

SharedMemory buf 布局:
┌───────────┐┌─────────────────────────────┐
│ n (4字节) ││ pickle 数据 (n 字节)        │
│ 数据长度  ││ [方法名, 参数1, 参数2, ...] │
└───────────┘└─────────────────────────────┘
   little-endian int  任意 pickle 对象

- 写入：先写 4 字节长度，再写 pickle 数据，最后 `event.set()` 唤醒。
- 读取：先 `event.wait()` 等待，读长度，再读对应字节解包。
- 这是个**最小化的 RPC 协议**：rank0 决定"调什么"，通过共享内存广播，所有 rank 同步执行同名方法。

### 3.3 `allocate_kv_cache`：显存预算 + 分发到各层

理论见 [第 2c 部分 §6](02c-加速并行与采样.md)。看代码：

```python
def allocate_kv_cache(self):
    free, total = torch.cuda.mem_get_info()
    used = total - free
    peak = torch.cuda.memory_stats()["allocated_bytes.all.peak"]
    current = torch.cuda.memory_stats()["allocated_bytes.all.current"]
    num_kv_heads = hf_config.num_key_value_heads // self.world_size   # GQA + TP
    head_dim = getattr(hf_config, "head_dim", hf_config.hidden_size // hf_config.num_attention_heads)
    block_bytes = 2 * hf_config.num_hidden_layers * self.block_size * num_kv_heads * head_dim * hf_config.dtype.itemsize
    config.num_kvcache_blocks = int(total * config.gpu_memory_utilization - used - peak + current) // block_bytes
    self.kv_cache = torch.empty(2, hf_config.num_hidden_layers, config.num_kvcache_blocks,
                                self.block_size, num_kv_heads, head_dim)   # ★ 大张量
    layer_id = 0
    for module in self.model.modules():
        if hasattr(module, "k_cache") and hasattr(module, "v_cache"):
            module.k_cache = self.kv_cache[0, layer_id]    # 各层 view 引用自己的切片
            module.v_cache = self.kv_cache[1, layer_id]
            layer_id += 1
```

要点（对应理论）：

- `block_bytes`：就是 [第 1 部分 §4.3](01-全局视角.md) / [第 2b 部分 §1](02b-引擎核心机制.md) 推导的每块字节数公式。
- `num_kvcache_blocks = (total·util - used - peak + current) // block_bytes`：[第 2c 部分 §6.3](02c-加速并行与采样.md) 讲过 `-peak + current` 的含义。
- `num_kv_heads // world_size`：TP 下每卡分到的 KV 头数（[第 2c 部分 §2](02c-加速并行与采样.md)）。
- 末尾 `for module in self.model.modules()`：遍历所有子模块，给每个 Attention 层挂上自己那层的 K/V 切片（view，零拷贝）。这是 [第 2b 部分 §1.2](02b-引擎核心机制.md) 讲的"大张量 + 各层 view"。

### 3.4 `prepare_prefill`：最难的 slot_mapping 计算 ⭐

这是全项目最绕的函数之一。目标：为 prefill 的每个 token 算出它的 K/V 该写到 KV cache 的哪个 slot。

```python
def prepare_prefill(self, seqs):
    input_ids, positions, slot_mapping = [], [], []
    cu_seqlens_q = [0]; cu_seqlens_k = [0]      # flash attention varlen 的边界
    for seq in seqs:
        start = seq.num_cached_tokens            # 已缓存的起点（prefix cache 命中部分跳过）
        seqlen_q = seq.num_scheduled_tokens      # 本步算多少
        end = start + seqlen_q
        seqlen_k = end                            # K 的长度 = 从 0 到 end（要看全部历史）
        input_ids.extend(seq[start:end])
        positions.extend(range(start, end))       # RoPE 位置 = 绝对位置
        cu_seqlens_q.append(cu_seqlens_q[-1] + seqlen_q)   # varlen 累积边界
        cu_seqlens_k.append(cu_seqlens_k[-1] + seqlen_k)
        ...
        # ★ 下面是 slot_mapping 的跨块计算
        start_block = start // self.block_size
        end_block = (end + self.block_size - 1) // self.block_size
        for i in range(start_block, end_block):
            slot_start = seq.block_table[i] * self.block_size
            if i == start_block:
                slot_start += start % self.block_size       # 起始块：加上块内偏移
            if i != end_block - 1:
                slot_end = seq.block_table[i] * self.block_size + self.block_size   # 中间整块
            else:
                slot_end = seq.block_table[i] * self.block_size + end - i * self.block_size  # 末块到 end
            slot_mapping.extend(range(slot_start, slot_end))
```

**图解 slot_mapping 的计算**（假设 block_size=4）：

```
某序列要算 [start=2, end=11) 这段 token（共9个）:
逻辑块:    块0(t0-3)  块1(t4-7)  块2(t8-11)
            └─start=2 在这    end=11 在块2 ─┘
block_table: [..., 5, 2, 7]   (逻辑块0→物理5, 逻辑块1→物理2, 逻辑块2→物理7)  示意

start_block = 2//4 = 0
end_block   = (11+3)//4 = 3   → 遍历 i = 0,1,2

i=0 (起始块): 物理块 block_table[0]
   slot_start = block_table[0]*4 + 2%4 = X*4 + 2   ← 从块内偏移2开始
   slot_end   = block_table[0]*4 + 4                ← 到块尾（因为不是末块）
   → range(slot_start, slot_end) = 这块的后2个slot

i=1 (中间块): 物理块 block_table[1]
   slot_start = block_table[1]*4                     ← 块首（不是起始块）
   slot_end   = block_table[1]*4 + 4                 ← 整块（不是末块）
   → 这块的4个slot

i=2 (末块): 物理块 block_table[2]
   slot_start = block_table[2]*4
   slot_end   = block_table[2]*4 + 11 - 2*4 = ...   ← 只到 end，不到块尾
   → 这块的前3个slot

合起来 slot_mapping: [起始块后2个, 中间块4个, 末块前3个] 共9个 = seqlen_q ✓
```

> 🧠 **本质**：把"逻辑上连续的 [start,end) 这段 token"，通过 block_table 翻译成"物理上可能跨多个不连续块的 slot 序列"。这就是 PagedAttention 在数据准备阶段的体现。

最后：

```python
if cu_seqlens_k[-1] > cu_seqlens_q[-1]:    # prefix cache: K比Q多（命中部分）
    block_tables = self.prepare_block_tables(seqs)   # 要传 block_table 给 flash attention
```

> 当命中 prefix cache 时，`seqlen_k > seqlen_q`（K 要看包括缓存前缀的全部历史），attention 要用 `block_table` 去 paged cache 里读历史 KV。否则 K 和 Q 一样长，直接用刚算的 K/V（不必查 cache）。

### 3.5 `prepare_decode`：单点 slot_mapping

decode 每个序列只算 1 个 token（last_token），slot_mapping 退化成单个值：

```python
def prepare_decode(self, seqs):
    input_ids, positions, slot_mapping, context_lens = [], [], [], []
    for seq in seqs:
        input_ids.append(seq.last_token)              # 上一步生成的 token
        positions.append(len(seq) - 1)                 # 它的位置
        context_lens.append(len(seq))                  # 历史 KV 长度
        slot_mapping.append(seq.block_table[-1] * self.block_size + seq.last_block_num_tokens - 1)
    ...
    block_tables = self.prepare_block_tables(seqs)     # decode 一定要 block_table（要读全部历史）
```

`slot = block_table[-1] * block_size + last_block_num_tokens - 1`：last_token 写入"最后一个物理块、块内第 (last_block_num_tokens-1) 个位置"。推导见 [第 2b 部分 §1.3](02b-引擎核心机制.md)。

> decode 时 `context_lens` 告诉 flash attention "这个序列的历史有多长"，配合 `block_table` 去 paged cache 读历史 K/V。

### 3.6 `run_model`：eager vs CUDA Graph 回放

```python
def run_model(self, input_ids, positions, is_prefill):
    if is_prefill or self.enforce_eager or input_ids.size(0) > 512:
        return self.model.compute_logits(self.model(input_ids, positions))   # eager 直跑
    else:
        bs = input_ids.size(0)
        context = get_context()
        graph = self.graphs[next(x for x in self.graph_bs if x >= bs)]   # 找≥bs的最小桶
        graph_vars = self.graph_vars
        graph_vars["input_ids"][:bs] = input_ids        # 把实际数据填进桶前 bs 位
        graph_vars["positions"][:bs] = positions
        graph_vars["slot_mapping"].fill_(-1)            # 先全填 -1（占位）
        graph_vars["slot_mapping"][:bs] = context.slot_mapping
        graph_vars["context_lens"].zero_(); graph_vars["context_lens"][:bs] = context.context_lens
        graph_vars["block_tables"][:bs, :...] = context.block_tables
        graph.replay()                                  # ★ 一键回放
        return self.model.compute_logits(graph_vars["outputs"][:bs])
```

- 理论见 [第 2c 部分 §3](02c-加速并行与采样.md)：decode 用 graph 省 launch 开销，prefill 不用。
- `next(x for x in self.graph_bs if x >= bs)`：在 `[1,2,4,8,16,...]` 里找第一个 ≥ 实际 bs 的桶。
- `slot_mapping.fill_(-1)`：多余位置填 -1，让 [store_kvcache kernel](../nanovllm/layers/attention.py) 的 `if slot == -1: return` 跳过它们（[第 2c 部分 §1.8](02c-加速并行与采样.md)）。
- `graph.replay()`：一次提交整张图，省掉上百次 kernel launch。

### 3.7 `capture_cudagraph`：录制细节

```python
def capture_cudagraph(self):
    max_bs = min(self.config.max_num_seqs, 512)
    self.graph_bs = [1, 2, 4, 8] + list(range(16, max_bs + 1, 16))
    self.graphs = {}
    self.graph_pool = None
    for bs in reversed(self.graph_bs):                  # ★ 从大到小录
        graph = torch.cuda.CUDAGraph()
        set_context(False, slot_mapping=slot_mapping[:bs], ...)
        outputs[:bs] = self.model(input_ids[:bs], positions[:bs])   # warmup（必须！）
        with torch.cuda.graph(graph, self.graph_pool):              # 录制
            outputs[:bs] = self.model(input_ids[:bs], positions[:bs])
        if self.graph_pool is None:
            self.graph_pool = graph.pool()              # 第一个 graph 建 pool
        self.graphs[bs] = graph
        torch.cuda.synchronize()
```

两个细节：

1. **`reversed`（从大到小录）**：所有 graph 共享一个 `graph_pool`（工作区显存）。如果从小到大录，小 graph 先占走 pool 的某些地址，大 graph 可能放不下。从大到小录，大 graph 先定下整体布局，小 graph 复用其池的空闲部分——这是 CUDA Graph 共享 pool 的最佳实践。
2. **warmup 必不可少**：录制前必须先跑一次 `outputs[:bs] = self.model(...)`。因为 PyTorch/CUDA 第一次执行时会做内存分配、缓存策略调整，地址不稳定。等它稳定后再录，图里的地址才正确。
3. **capture 时传的是占位零张量**：上面 `set_context(False, slot_mapping=slot_mapping[:bs], ...)` 里的 `slot_mapping` 等都是 capture 前 `torch.zeros(...)` 出来的**占位张量，不是真实数据**。真实参数是回放时（§3.6）通过 `graph_vars["slot_mapping"][:bs] = context.slot_mapping` 注入的。录制只固化"操作序列 + 张量地址"，数据留到回放时填。

> 📐 录制后，`self.graph_vars` 保存了 input_ids / positions / slot_mapping / outputs 等张量的**引用**。回放时往这些张量里填新数据，再 `graph.replay()`——graph 录的是"操作序列"，数据是"插槽"，可反复填不同数据。

### 3.8 `warmup_model`：为什么先跑最大 batch

```python
def warmup_model(self):
    torch.cuda.empty_cache()
    torch.cuda.reset_peak_memory_stats()
    seq_len = min(max_num_batched_tokens, max_model_len)
    num_seqs = min(max_num_batched_tokens // seq_len, max_num_seqs)
    seqs = [Sequence([0] * seq_len) for _ in range(num_seqs)]   # 假数据，最大规模
    for seq in seqs: seq.num_scheduled_tokens = seq_len
    self.run(seqs, True)                          # 跑一次最大 prefill
    torch.cuda.empty_cache()
```

[第 2c 部分 §6.2](02c-加速并行与采样.md) 讲过：激活显存随 batch 动态变化。直接测当前显存不准，必须先跑一次**最大可能规模**的 prefill，把峰值激活显存"逼出来"，这样后面 `allocate_kv_cache` 测 `peak` 才准。否则 KV cache 算多了，运行时一撑大就 OOM。

### 3.9 `run`：一步推理的串联

```python
def run(self, seqs, is_prefill):
    input_ids, positions = self.prepare_prefill(seqs) if is_prefill else self.prepare_decode(seqs)
    temperatures = self.prepare_sample(seqs) if self.rank == 0 else None   # 只 rank0 采样
    logits = self.run_model(input_ids, positions, is_prefill)
    token_ids = self.sampler(logits, temperatures).tolist() if self.rank == 0 else None
    reset_context()
    return token_ids
```

- 准备数据 → 跑模型 → 采样。
- **只有 rank 0 采样并返回 token_ids**（其他 rank 返回 None）。因为采样只需要 logits（各卡 gather 后 rank0 有完整 logits），不必每个卡都算。这是个小的负载均衡优化。

## 层 4：模型层 [`models/qwen3.py`](../nanovllm/models/qwen3.py)

### 4.1 整体：Qwen3ForCausalLM

```python
class Qwen3ForCausalLM(nn.Module):
    packed_modules_mapping = {                # ★ 权重加载映射：HF分开存→nano合并
        "q_proj": ("qkv_proj", "q"),
        "k_proj": ("qkv_proj", "k"),
        "v_proj": ("qkv_proj", "v"),
        "gate_proj": ("gate_up_proj", 0),
        "up_proj": ("gate_up_proj", 1),
    }
    def __init__(self, config):
        super().__init__()
        self.model = Qwen3Model(config)
        self.lm_head = ParallelLMHead(config.vocab_size, config.hidden_size)
        if config.tie_word_embeddings:
            self.lm_head.weight.data = self.model.embed_tokens.weight.data   # 共享权重
```

- `packed_modules_mapping`：告诉 [`loader.py`](../nanovllm/utils/loader.py) 怎么把 HuggingFace 分开存的 q/k/v 权重装进合并的 qkv_proj（[第 2a §3.3](02a-模型本体理论.md)、[第 2c §2.5](02c-加速并行与采样.md)）。
- `tie_word_embeddings`：输入 embedding 和输出 LM head **共享权重**（很多小模型这么做省参数）。

### 4.2 Qwen3Model：Embedding + N 层 + Norm

```python
class Qwen3Model(nn.Module):
    def __init__(self, config):
        self.embed_tokens = VocabParallelEmbedding(config.vocab_size, config.hidden_size)
        self.layers = nn.ModuleList([Qwen3DecoderLayer(config) for _ in range(config.num_hidden_layers)])
        self.norm = RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
    def forward(self, input_ids, positions):
        hidden_states = self.embed_tokens(input_ids)     # 查表：id → 向量
        residual = None
        for layer in self.layers:                         # 过 N 层
            hidden_states, residual = layer(positions, hidden_states, residual)
        hidden_states, _ = self.norm(hidden_states, residual)   # 最终归一化
        return hidden_states
```

### 4.3 Qwen3DecoderLayer：残差 + 两个子层

```python
class Qwen3DecoderLayer(nn.Module):
    def forward(self, positions, hidden_states, residual):
        if residual is None:                              # 第一层：还没有残差
            hidden_states, residual = self.input_layernorm(hidden_states), hidden_states
        else:                                             # 后续层：融合残差归一化
            hidden_states, residual = self.input_layernorm(hidden_states, residual)
        hidden_states = self.self_attn(positions, hidden_states)        # ① Attention
        hidden_states, residual = self.post_attention_layernorm(hidden_states, residual)
        hidden_states = self.mlp(hidden_states)                          # ② MLP
        return hidden_states, residual
```

注意"融合残差"的设计（[第 2a §2.3](02a-模型本体理论.md) 的 `add_rms_forward`）：`RMSNorm(x, residual)` 一次完成"加残差 + 归一化"，并返回新的 residual。这把残差的读写和归一化融合，省一次显存往返——对访存敏感的 decode 很关键。

### 4.4 Qwen3Attention：完整 forward

```python
class Qwen3Attention(nn.Module):
    def forward(self, positions, hidden_states):
        qkv = self.qkv_proj(hidden_states)                       # 合并的 QKV 矩阵乘
        q, k, v = qkv.split([self.q_size, self.kv_size, self.kv_size], dim=-1)
        q = q.view(-1, self.num_heads, self.head_dim)
        k = k.view(-1, self.num_kv_heads, self.head_dim)
        v = v.view(-1, self.num_kv_heads, self.head_dim)
        if not self.qkv_bias:
            q = self.q_norm(q); k = self.k_norm(k)              # ★ Qwen3 独有
        q, k = self.rotary_emb(positions, q, k)                 # RoPE
        o = self.attn(q, k, v)                                  # Flash Attention + 存 KV
        output = self.o_proj(o.flatten(1, -1))                  # 输出投影（行并行）
        return output
```

逐步对应 [第 2a 部分 §4.6](02a-模型本体理论.md) 的数据流图：qkv_proj → split → reshape → q/k_norm → RoPE → attn → o_proj。

### 4.5 Qwen3MLP：SwiGLU

```python
class Qwen3MLP(nn.Module):
    def forward(self, x):
        gate_up = self.gate_up_proj(x)     # 合并矩阵（gate+up）
        x = self.act_fn(gate_up)           # SiluAndMul: SiLU(gate)⊙up（第2a §3）
        x = self.down_proj(x)
        return x
```
