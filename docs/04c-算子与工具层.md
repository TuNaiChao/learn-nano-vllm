## 层 5：算子层 [`layers/`](../nanovllm/layers/)

### 5.1 [`layers/attention.py`](../nanovllm/layers/attention.py) —— Triton kernel + Flash Attention

#### (1) store_kvcache：把新 K/V 散射写进 paged cache ⭐

理论见 [第 2c 部分 §1.8](02c-加速并行与采样.md)。逐行读 triton kernel：

```python
@triton.jit
def store_kvcache_kernel(
    key_ptr, key_stride, value_ptr, value_stride,     # 新算出的 K, V 张量
    k_cache_ptr, v_cache_ptr,                         # paged KV cache
    slot_mapping_ptr,                                 # 每个 token 的目标 slot
    D: tl.constexpr,                                  # 每个token的K维度 = num_heads*head_dim（编译期常量）
):
    idx = tl.program_id(0)                  # 线程块 id = 处理第 idx 个 token
    slot = tl.load(slot_mapping_ptr + idx)  # 读这个 token 要写到哪个 slot
    if slot == -1: return                   # 占位（CUDA graph 多余位置）跳过
    key_offsets   = idx * key_stride   + tl.arange(0, D)   # key 张量里本 token 的 D 个元素偏移
    value_offsets = idx * value_stride + tl.arange(0, D)
    key   = tl.load(key_ptr   + key_offsets)              # 从 key 读出本 token 的 K
    value = tl.load(value_ptr + value_offsets)            # 读 V
    cache_offsets = slot * D + tl.arange(0, D)            # cache 里 slot 位置的偏移
    tl.store(k_cache_ptr + cache_offsets, key)            # 散射写 K
    tl.store(v_cache_ptr + cache_offsets, value)          # 散射写 V
```

**关键概念**：

- `tl.program_id(0)`：triton 的并行维度。`store_kvcache_kernel[(N,)]` 启动 N 个线程块，每个处理一个 token，完全并行。
- `tl.arange(0, D)`：生成 `[0,1,...,D-1]`，配合指针做向量化 load/store（一次搬 D 个元素）。
- `slot * D + arange`：把"逻辑上的第 slot 个 slot"翻译成"物理上连续 D 个元素的偏移"。这正是 [第 2b 部分 §1.3](02b-引擎核心机制.md) 的 slot 定位。
- `D: tl.constexpr`：编译期常量，triton 据此优化。

host 包装函数：

```python
def store_kvcache(key, value, k_cache, v_cache, slot_mapping):
    N, num_heads, head_dim = key.shape
    D = num_heads * head_dim
    assert key.stride(-1) == 1 and value.stride(-1) == 1            # 最内维连续
    assert key.stride(1) == head_dim and value.stride(1) == head_dim # 头维步长
    assert k_cache.stride(1) == D and v_cache.stride(1) == D
    store_kvcache_kernel[(N,)](key, key.stride(0), value, value.stride(0),
                               k_cache, v_cache, slot_mapping, D)
```

> 这些 `stride` 断言确保张量内存布局符合 kernel 假设（最内维连续等）。triton kernel 直接操作指针，不检查布局，所以 host 侧要先断言。这是写高性能 kernel 的常规严谨做法。

#### (2) Attention.forward：prefill / decode 分支

```python
class Attention(nn.Module):
    def forward(self, q, k, v):
        context = get_context()
        k_cache, v_cache = self.k_cache, self.v_cache
        if k_cache.numel() and v_cache.numel():                     # 有 cache（非 warmup）
            store_kvcache(k, v, k_cache, v_cache, context.slot_mapping)   # 先把新 K/V 存进 cache
        if context.is_prefill:
            if context.block_tables is not None:                    # 命中 prefix cache
                k, v = k_cache, v_cache                             # 用 cache 里的全部历史 K/V
            o = flash_attn_varlen_func(q, k, v,                     # varlen attention
                max_seqlen_q=context.max_seqlen_q, cu_seqlens_q=context.cu_seqlens_q,
                max_seqlen_k=context.max_seqlen_k, cu_seqlens_k=context.cu_seqlens_k,
                softmax_scale=self.scale, causal=True, block_table=context.block_tables)
        else:                                                        # decode
            o = flash_attn_with_kvcache(q.unsqueeze(1), k_cache, v_cache,
                cache_seqlens=context.context_lens, block_table=context.block_tables,
                softmax_scale=self.scale, causal=True)
        return o
```

要点：

- **先存后算**：先 `store_kvcache` 把当前步的 K/V 写进 cache，再做 attention（attention 要读包括刚写入的全部历史）。
- **prefix cache 分支**：`block_tables is not None` 表示命中了前缀缓存（[第 4b 部分 §3.4](04b-执行层与模型层.md)），这时 K/V 直接指向整个 cache（`k, v = k_cache, v_cache`），flash attention 靠 `block_table` 去 cache 里取。
- **两个 flash 接口**：prefill 用 `varlen_func`（变长拼批，[第 2c §1.7](02c-加速并行与采样.md)），decode 用 `with_kvcache`（paged cache 上算）。

### 5.2 [`layers/linear.py`](../nanovllm/layers/linear.py) —— 各种并行 Linear ⭐

这是 TP 的核心实现（理论见 [第 2c 部分 §2](02c-加速并行与采样.md)）。重点看每种 `weight_loader` 怎么切分权重。

#### LinearBase：基类

```python
class LinearBase(nn.Module):
    def __init__(self, input_size, output_size, bias=False, tp_dim=None):
        self.tp_dim = tp_dim                  # 切哪个维度（0=输出列, 1=输入行）
        self.tp_rank = dist.get_rank()
        self.tp_size = dist.get_world_size()
        self.weight = nn.Parameter(torch.empty(output_size, input_size))
        self.weight.weight_loader = self.weight_loader   # ★ 把 loader 挂到参数上
```

> 注意 `self.weight.weight_loader = self.weight_loader`：把"怎么加载这个参数"的方法**挂到参数对象上**。这样 loader.py 遍历参数时，能通过 `getattr(param, "weight_loader")` 拿到对应的切分逻辑。这是一种"参数自带加载说明"的设计。

#### ColumnParallelLinear：切输出维

```python
class ColumnParallelLinear(LinearBase):
    def __init__(self, input_size, output_size, bias=False):
        super().__init__(input_size, divide(output_size, tp_size), bias, 0)   # 输出维除以 tp_size，tp_dim=0
    def weight_loader(self, param, loaded_weight):
        shard_size = param.data.size(self.tp_dim)           # 本卡那份的大小
        start_idx = self.tp_rank * shard_size               # 本卡负责的起点
        loaded_weight = loaded_weight.narrow(self.tp_dim, start_idx, shard_size)   # 切片
        param.data.copy_(loaded_weight)
    def forward(self, x):
        return F.linear(x, self.weight, self.bias)
```

`weight` 形状 `[output/tp, input]`。加载时把完整权重的 `[rank*shard : (rank+1)*shard, :]` 切出来拷给本卡（[第 2c §2.6](02c-加速并行与采样.md) 的 narrow 切片）。

#### MergedColumnParallelLinear：两个 output 合并（gate+up）

```python
class MergedColumnParallelLinear(ColumnParallelLinear):
    def __init__(self, input_size, output_sizes, bias=False):
        self.output_sizes = output_sizes                     # [intermediate, intermediate]
        super().__init__(input_size, sum(output_sizes), bias)
    def weight_loader(self, param, loaded_weight, loaded_shard_id):   # shard_id=0或1
        shard_offset = sum(self.output_sizes[:loaded_shard_id]) // self.tp_size  # 本shard在合并矩阵里的起点
        shard_size = self.output_sizes[loaded_shard_id] // self.tp_size
        param_data = param_data.narrow(self.tp_dim, shard_offset, shard_size)
        loaded_weight = loaded_weight.chunk(self.tp_size, self.tp_dim)[self.tp_rank]   # 按tp切
        param_data.copy_(loaded_weight)
```

合并矩阵 `[gate(intermediate) ; up(intermediate)]`，每部分各自按 TP 切。`loaded_shard_id` 告诉 loader"现在加载的是 gate(0) 还是 up(1)"。

#### QKVParallelLinear：q/k/v 各自切

```python
class QKVParallelLinear(ColumnParallelLinear):
    def weight_loader(self, param, loaded_weight, loaded_shard_id):   # "q"/"k"/"v"
        if loaded_shard_id == "q":
            shard_size = self.num_heads * self.head_dim;     shard_offset = 0
        elif loaded_shard_id == "k":
            shard_size = self.num_kv_heads * self.head_dim;  shard_offset = self.num_heads * self.head_dim
        else:  # v
            shard_size = self.num_kv_heads * self.head_dim
            shard_offset = self.num_heads * self.head_dim + self.num_kv_heads * self.head_dim
        param_data = param_data.narrow(self.tp_dim, shard_offset, shard_size)
        loaded_weight = loaded_weight.chunk(self.tp_size, self.tp_dim)[self.tp_rank]
        param_data.copy_(loaded_weight)
```

注意 q/k/v 的 `shard_size` **不同**（q 用 `num_heads`，k/v 用 `num_kv_heads`）——因为 GQA 下 KV 头少（[第 2a §4.2](02a-模型本体理论.md)）。合并矩阵布局是 `[Q | K | V]`，各自定位 offset。

#### RowParallelLinear：切输入维 + all_reduce

```python
class RowParallelLinear(LinearBase):
    def __init__(self, input_size, output_size, bias=False):
        super().__init__(divide(input_size, tp_size), output_size, bias, 1)   # 输入维除以 tp_size，tp_dim=1
    def forward(self, x):
        y = F.linear(x, self.weight, self.bias if self.tp_rank == 0 else None)
        if self.tp_size > 1:
            dist.all_reduce(y)            # ★ 行并行末尾 all_reduce（第2c §2.3）
        return y
```

- `weight` 形状 `[output, input/tp]`，每卡只有自己那份输入。
- forward 后 `all_reduce` 求和（[第 2c §2.2](02c-加速并行与采样.md)）。`bias` 只在 rank 0 加（避免 all_reduce 后 bias 被加 p 次）。

### 5.3 [`layers/rotary_embedding.py`](../nanovllm/layers/rotary_embedding.py) —— RoPE

理论见 [第 2a 部分 §1](02a-模型本体理论.md)。代码细节：

```python
class RotaryEmbedding(nn.Module):
    def __init__(self, head_size, rotary_dim, max_position_embeddings, base):
        inv_freq = 1.0 / (base ** (torch.arange(0, rotary_dim, 2, dtype=torch.float) / rotary_dim))  # θ_j
        t = torch.arange(max_position_embeddings, dtype=torch.float)                                  # 位置 m
        freqs = torch.einsum("i,j -> ij", t, inv_freq)                                                # m·θ_j
        cos, sin = freqs.cos(), freqs.sin()
        self.register_buffer("cos_sin_cache", torch.cat((cos, sin), dim=-1).unsqueeze_(1), persistent=False)
    @torch.compile
    def forward(self, positions, query, key):
        cos_sin = self.cos_sin_cache[positions]        # 按位置查表
        cos, sin = cos_sin.chunk(2, dim=-1)
        query = apply_rotary_emb(query, cos, sin)      # 复数乘法等价实现（第2a §1.6）
        key = apply_rotary_emb(key, cos, sin)
        return query, key
```

- `register_buffer(..., persistent=False)`：把 cos/sin 表注册为 buffer（随模型一起搬设备），但 `persistent=False` 表示**不存进 checkpoint**（因为可以重新算，不必占磁盘）。
- `@lru_cache(1)` 在 [`get_rope`](../nanovllm/layers/rotary_embedding.py) 上，让所有层共用一个实例（[第 3 部分 C2](03-Python语法清单.md)）。

### 5.4 [`layers/embed_head.py`](../nanovllm/layers/embed_head.py) —— Embedding + LM Head

#### VocabParallelEmbedding：词表分片

```python
class VocabParallelEmbedding(nn.Module):
    def __init__(self, num_embeddings, embedding_dim):
        self.num_embeddings_per_partition = num_embeddings // tp_size    # 本卡持有多少 token
        self.vocab_start_idx = self.num_embeddings_per_partition * tp_rank
        self.vocab_end_idx = self.vocab_start_idx + self.num_embeddings_per_partition
        self.weight = nn.Parameter(torch.empty(self.num_embeddings_per_partition, embedding_dim))
    def forward(self, x):
        if self.tp_size > 1:
            mask = (x >= self.vocab_start_idx) & (x < self.vocab_end_idx)   # 本卡负责哪些 token
            x = mask * (x - self.vocab_start_idx)                           # 映射到本地索引（不在范围的变0）
        y = F.embedding(x, self.weight)                                     # 查表
        if self.tp_size > 1:
            y = mask.unsqueeze(1) * y                                       # 不在范围的输出置0
            dist.all_reduce(y)                                              # 求和（每处只在负责的卡有值）
        return y
```

**mask 机制**：词表按段分给各卡。某个 token id 只有"负责它的那卡"查表得到正确向量，其他卡对它输出 0。`all_reduce` 求和后，每个 token 的正确向量就凑齐了。巧妙的"分段查表 + 求和合并"。

#### ParallelLMHead：只算最后一个 token + gather ⭐

```python
class ParallelLMHead(VocabParallelEmbedding):
    def forward(self, x):
        context = get_context()
        if context.is_prefill:
            last_indices = context.cu_seqlens_q[1:] - 1   # ★ 每个序列最后一个 token 的索引
            x = x[last_indices].contiguous()              # 只对这些位置算 logits
        logits = F.linear(x, self.weight)
        if self.tp_size > 1:
            all_logits = [torch.empty_like(logits) for _ in range(tp_size)] if rank==0 else None
            dist.gather(logits, all_logits, 0)            # 各卡 logits 收集到 rank0
            logits = torch.cat(all_logits, -1) if rank==0 else None
        return logits
```

**两个优化**：

1. **prefill 只算最后一个 token 的 logits**：prefill 算完整个 prompt，但只有**每个序列最后一个 token** 需要预测下一个并采样。`last_indices = cu_seqlens_q[1:] - 1` 精确定位拼接序列里这些位置。这把 LM Head 的计算量从 `O(总token数 × vocab)` 降到 `O(序列数 × vocab)`，省巨多（[第 4b 部分](04b-执行层与模型层.md) 的 cu_seqlens 这里又派上用场）。
2. **gather 到 rank0**：词表分片在各卡，logits 也分片。gather 把各卡 logits 收集到 rank0 拼成完整词表分布，rank0 据此采样。

## 层 6：工具层 [`utils/`](../nanovllm/utils/)

### 6.1 [`utils/context.py`](../nanovllm/utils/context.py) —— 全局上下文

```python
@dataclass(slots=True)
class Context:
    is_prefill: bool = False
    cu_seqlens_q, cu_seqlens_k: ... = None
    max_seqlen_q, max_seqlen_k: int = 0
    slot_mapping, context_lens, block_tables: ... = None

_CONTEXT = Context()
def get_context(): return _CONTEXT
def set_context(...): 
    global _CONTEXT              # 第3部分 E3
    _CONTEXT = Context(...)
def reset_context(): 
    global _CONTEXT
    _CONTEXT = Context()
```

**设计意图**：attention 层在模型深处（第 N 层），需要知道 `slot_mapping`、`block_table`、`is_prefill` 等当前推理的参数。如果靠函数参数层层传递，`forward(positions, hidden, slot_mapping, block_table, ...)` 会极其冗长。nano-vllm 用一个**模块级全局变量** `_CONTEXT` 存这些，任意深度的层 `get_context()` 即可拿到。

**调用时机**：

- `model_runner.prepare_prefill/decode` 调 `set_context(...)` 填好当前步的参数。
- 各层 attention 调 `get_context()` 读。
- `run` 结束后 `reset_context()` 清空。

> ⚖️ **设计权衡**：全局变量的好处是省去长参数链、代码简洁；坏处是隐式依赖（attention 依赖某个全局被正确设置）、不利于并发。nano-vllm 选了简洁——因为它是单线程驱动的推理引擎，没有并发问题。这是"教学级代码"用可读性换严谨性的典型取舍。

### 6.2 [`utils/loader.py`](../nanovllm/utils/loader.py) —— 权重分片加载

```python
def default_weight_loader(param, loaded_weight):
    param.data.copy_(loaded_weight)

def load_model(model, path):
    packed_modules_mapping = getattr(model, "packed_modules_mapping", {})   # qkv_proj 等映射
    for file in glob(os.path.join(path, "*.safetensors")):                  # 所有权重文件
        with safe_open(file, "pt", "cpu") as f:                            # 第3部分 E2: with
            for weight_name in f.keys():
                for k in packed_modules_mapping:                            # 找是否是"合并矩阵"的一部分
                    if k in weight_name:
                        v, shard_id = packed_modules_mapping[k]
                        param_name = weight_name.replace(k, v)              # q_proj→qkv_proj
                        param = model.get_parameter(param_name)
                        weight_loader = getattr(param, "weight_loader")     # 取参数自带的 loader
                        weight_loader(param, f.get_tensor(weight_name), shard_id)
                        break
                else:                                                        # 第3部分 D1: for-else
                    param = model.get_parameter(weight_name)
                    weight_loader = getattr(param, "weight_loader", default_weight_loader)
                    weight_loader(param, f.get_tensor(weight_name))
```

**流程**：

1. 遍历所有 `.safetensors` 文件（`glob` 找）。
2. 对每个权重名，先查 `packed_modules_mapping`（[第 4b §4.1](04b-执行层与模型层.md)）——如果是 `q_proj/k_proj/v_proj` 这类，它要装进合并的 `qkv_proj`，用专门的 `weight_loader(param, weight, shard_id)`（带 shard_id 区分 q/k/v）。
3. 都不匹配（`for-else` 的 else），就是普通权重，用默认 loader 整体拷贝。
4. `getattr(param, "weight_loader", default)`：取参数自带的切分逻辑（[第 5.2 节](#52-layerslinearpy--各种并行-linear-) 各种 Linear 挂的 loader），没有就用默认。

> 🧠 这套设计的精妙：**每个 Parameter 自己知道"我该怎么被加载/切分"**（通过挂在上面的 `weight_loader`），loader.py 只负责遍历和分发。新增一种并行策略，只需写新的 Linear 类并挂 loader，loader.py 不用改。**开闭原则**的好例子。

## 本篇小结 + 第 4 部分收官

最后一块拼图补齐：

- **attention**：triton kernel `store_kvcache` 用 `program_id` 并行散射写 KV（slot==-1 跳过占位）；Attention.forward 先存后算，prefill 用 varlen、decode 用 with_kvcache，命中 prefix cache 时直接读 cache。
- **linear**：ColumnParallel（切输出）、RowParallel（切输入+all_reduce）、MergedColumnParallel（gate+up）、QKVParallel（q/k/v 各切）；每种靠挂在 Parameter 上的 `weight_loader` 实现各自的切分。
- **embed_head**：VocabParallelEmbedding 用 mask + all_reduce 做词表分片查表；ParallelLMHead 在 prefill **只算每个序列最后一个 token** 的 logits（省巨量计算）+ gather 到 rank0。
- **context**：全局 `_CONTEXT` 存当前步参数，避免长参数链。
- **loader**：遍历 safetensors，靠 `packed_modules_mapping` + Parameter 自带的 `weight_loader` 完成分片加载（开闭原则）。
